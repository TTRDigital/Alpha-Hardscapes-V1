# Alpha Hardscapes website (V1 redesign)

A modern redesign of alphahardscapes.com (Southern Connecticut hardscaping, paver and masonry contractor), built with **Next.js 16**, **Tailwind CSS 4** and **Sanity** (Studio embedded at `/studio`). Built by TTR Digital Marketing.

- **Same addresses, same words:** every live page keeps its exact URL, title, meta description, H1, body text, FAQs and internal links (the SEO rules). Only the design changed. What was checked and what needs approval: [`docs/seo-migration-report.md`](docs/seo-migration-report.md).
- **Editable without code:** every page is a list of sections and blocks in Sanity, plus site settings (phone, email, hours, menus, forms). Guide for the client: [`docs/editing-with-sanity.md`](docs/editing-with-sanity.md).
- **Complete on day one:** the live site's content is in `content/legacy/site.data.ts` (generated by `scripts/migrate/import-live.mjs` from the live CMS export) and is seeded into Sanity by `npm run seed`. If Sanity is empty or unreachable the site still builds and shows that content.
- **Publish → rebuild:** a Sanity webhook hits `/api/revalidate`, which clears the content cache and can call a Vercel deploy hook. Steps: [`docs/deploy-and-rebuild.md`](docs/deploy-and-rebuild.md).
- **Research behind the design:** [`docs/research-report.md`](docs/research-report.md) (105 sites, including "Lions Creek vs. the best of the 100") and the live-site inventory in [`docs/phase-0-live-site-audit.md`](docs/phase-0-live-site-audit.md).

## Quick start

```bash
npm install
cp .env.example .env.local      # optional: add the Sanity project ID to read from the CMS
npm run dev                     # http://localhost:3000 (site) and /studio (CMS)
```

Checks: `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`.

## How it is organised

| Folder | What is there |
|---|---|
| `app/(site)/` | Home and a catch-all route that serves every live address (pages, posts, blog lists, thank-you and ad pages) |
| `app/sitemap_index.xml/`, `app/feed/` | The live site's sitemap and RSS addresses |
| `app/studio/` | Sanity Studio at `/studio` |
| `app/api/lead/` | Quote forms → the same GoHighLevel webhook and payload as the live site (honeypot, fill timer, optional reCAPTCHA) |
| `app/api/season-lead/` | Form of the static `/patios-walkways/` ad page |
| `app/api/revalidate/` | Sanity publish webhook → cache revalidation (+ optional deploy hook) |
| `components/` | Section renderer (`page/`), forms (`forms/`), site chrome and tracking (`site/`), UI primitives |
| `content/site.ts`, `content/legacy/` | Built-in copy of the live site (also the seed source) and the photo alt text |
| `lib/content.ts` | Content API: Sanity first, built-in copy as fallback |
| `lib/sanity/` | Client, GROQ queries, image helpers |
| `sanity/schemas/` | CMS document types |
| `scripts/seed.ts` | Seeds Sanity with the built-in content and uploads the photos |
| `redirects.ts`, `content/redirects.json` | The live site's 711 redirects, carried over (one hop each) |
| `docs/` | Client guide, deploy guide, research report and Phase 0 audit |

## Environment variables

See `.env.example`. The site runs with none of them set. Secrets (`SANITY_API_TOKEN`, webhook secret, lead webhook, email key) live only in Vercel / GitHub secrets, never in code.

## Scripts

| Command | Purpose |
|---|---|
| `npm run dev` / `build` / `start` | Next.js |
| `npm run seed` | Add built-in content to Sanity (`-- --force` overwrites, `npm run seed:dry` previews) |
| `npm test` | Unit tests (every live address present, one H1, no street address or rating stars, redirects one hop to live pages, form keys, schema) |
| `npm run lint` / `typecheck` | ESLint / TypeScript |
